# Phase 4：攻速与固定攻击时间表

模型标识：`fixed_rate_v0.1_unverified`。用户未单独反馈时间表，但已确认随后完整Notebook战斗、日志及超时示例正确；见basic-duel.md和phase4-validation.md。时间规则仍是显式模型假设。

## 数学定义

- AS：有效攻速，单位为次/秒，必须为有限正数。
- T：攻击间隔，单位为秒/次，T = 1 / AS。
- 第n次攻击的时刻为t_n = n / AS，n从1开始。
- 例：AS=2，T=0.5；1秒窗口内的攻击在0.5、1.0秒发生。

## 模型约定，不是客户端精确规则

1. 第一击发生在一个完整间隔后，不在0秒免费攻击。
2. 攻速固定，不模拟前摇、弹道、施法、眩晕、移动或受伤后改变攻速的被动。
3. 时间窗口包含截止时刻；只接受浮点计算结果满足t_n<=duration的事件，不使用额外epsilon或每步取整。
4. 按序号计算绝对时间，不反复累加间隔。例如3/10直接得到0.3，而0.1+0.1+0.1可能略大于0.3。
5. 时间表只描述单个单位的计划时刻，不处理死亡、同时攻击、伤害或胜负。这些由下一步事件引擎处理。

## 版本相关攻速限制

尚未完成Patch 14.1上下限与特殊英雄例外的一手核验。默认不截断源攻速。TimingRules允许显式设置min_attack_speed/max_attack_speed，两者都默认为None。

测试中使用的0.5和5.0仅是自定义数学配置，不作为官方边界。源攻速为0.699999988079071时，第七击略晚于10秒；不要先四舍五入成0.7再排事件。

attack_times生成有限列表，最多允许约100000个候选事件的演示规模，防止误传巨大时间窗口耗尽内存。这是工具的资源保护，不是游戏攻速或次数限制。

## 接口与验证

- `effective_attack_speed(attack_speed, rules=None)`：检查并按可选上下限得到有效攻速。
- `attack_interval(attack_speed, rules=None)`：返回间隔。
- `attack_times(attack_speed, duration, rules=None)`：返回窗口内攻击时间列表；duration=0返回空列表。
