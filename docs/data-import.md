## Logic

1. `load_dataset`: reads CSV by column name, converts numeric strings to finite floats, decodes trait lists and ability JSON, and checks that IDs and source metadata correspond. It reuses the existing raw-file hash; no new export/hash audit is required.
2. `import_dataset`: performs all three table writes in one database transaction. Failure rolls back that import; it does not clear existing data.
3. The version ID is generated by PostgreSQL. An existing matching version is reused.
4. SQL parameter binding passes values separately from query text. Python lists adapt to `TEXT[]`; `Jsonb` adapts skill arrays to `JSONB`.
5. `ON CONFLICT ... DO NOTHING` adds only missing keys. It never updates existing rows. If a CSV is deliberately edited but retains the same version/hero keys, rerunning this command does not synchronize those edits into the database.
