# Phase 4：普通攻击1v1事件引擎

引擎标识：`basic_duel_v0.1`。这是使用真实源属性的简化普通攻击基线，不是完整TFT客户端复现。用户已确认Notebook完整战斗摘要、23条日志及5秒超时结果正确；见phase4-validation.md。

本文保留Phase 4基线说明。Phase 5引擎升级为basic_duel_v0.2，默认关闭暴击仍保持原数值；enable_crit=True和整数seed可启用暴击，新增暴击计数与日志字段。详见critical-strikes.md。

## 接口

`run_duel(stats_a, stats_b, max_duration=60.0, timing_rules=None, max_events=100000)`

两个输入都是不可变ChampionStats，必须属于同一数据库源版本。函数内部创建两份全新CombatState，上一场受伤状态不会进入下一场。结果为BattleResult，提供summary()和log_records()。

## 事件推进

1. t=0记录battle_start。
2. 两侧第一击在1/AS发生。小根堆中每侧最多保留一个待执行攻击。
3. 直接跳到最早事件时间，不使用固定毫秒步长。
4. 严格相同浮点时间的事件组成一个批次；不同时间不加epsilon合并。
5. 根据批次开始时双方存活状态生成全部攻击，之后应用伤害。
6. 记录本批攻击日志，再记录死亡；同批允许双方致命攻击全部生效。
7. 一方死亡立即结束，双方死亡为double_ko平局；否则安排下一击n/AS。
8. 截止时刻的攻击先结算；如果双方仍活着，按timeout平局结束，不比较剩余HP判胜。

## 简化与未核验项

- 所有普通攻击按源AD产生物理伤害，使用resistance_v0.1_unverified抗性模型。
- 固定攻速、默认无未经核验的上下限截断；可显式传入TimingRules。
- 默认双方始终在攻击范围内，没有棋盘移动、前摇或弹道。
- 无暴击、技能、被动、特殊攻击规则、装备、羁绊或赛季之星效果。
- 初始法力被记录，但不获得法力、不施法；不能把日志中的法力列当作已实现法力系统。
- 无随机机制，不提供虚构随机种子或胜率。相同输入和规则得到相同结果；重复运行不会产生额外随机信息。
- 同时结算是明确的模型选择，并非已证明Riot客户端采用该顺序。
- 事件资源上限触发时抛错，不伪装成超时平局。

## 日志语义

每个BattleEvent包含时间、事件类型、行动方与目标、原始/抗性后/实际扣血三种伤害、双方剩余HP及法力。

**同批次的两条攻击日志都显示该批结算完毕后的双方HP**，不能按日志行号理解为先后攻击。actor_side使用A/B区分同名同ID镜像战斗。

damage字段和摘要damage_a/damage_b是实际生命损失之和；过量部分另保存在damage_after_resistance。events为冻结事件元组；log_records返回可供DataFrame使用的新字典列表。

metadata记录引擎/伤害/时间模型版本、源版本ID、双方完整属性快照、时间和资源限制、攻速配置及已禁用机制。保留输入快照让之后的实验配置可追踪，不修改数据库。
